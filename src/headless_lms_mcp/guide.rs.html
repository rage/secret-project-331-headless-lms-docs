46const EDITING: &str = "\
47patch_page_content takes ops {op, path, from, through, value, position, to_page, label, at_text}.
48- add: value is a block or a list of blocks; position before/after a block path or start/end of a children list (\"\" or /<id>/innerBlocks).
49- replace /<id>: a block, keeping its id; fields you leave out keep their values; a container's replacement needs innerBlocks (use {\"clientId\":\"…\"} stubs to keep children).
50- replace /<id>/attributes/<name>: sets one attribute at any depth; a missing key is added. remove on it deletes the attribute.
51- replace on a children list or \"\": array rules: a stub keeps a block, a block with clientId replaces it, a block without one is new; leaving out an existing block or naming an unknown id is an error. Use this to reorder.
52- move/copy: from (+through) to path+position; to_page moves or copies to another page. move keeps ids, copy assigns new ones (a copied exercise becomes a new exercise without submissions).
53- remove: a block or a range (path + through).
54- wrap (path, through, value: the container), unwrap (path), split (path, at_text: the second block starts there), merge (from into path; from must be the next sibling).
55- Exercise blocks can be moved, copied and removed, not replaced or edited; patch_exercise edits an exercise's name, own deadline and instructions.
56- dry_run: true stages nothing and returns the diff; read_back reads the result in the same call.";

58const COURSE_STRUCTURE: &str = "\
59get_course_structure returns {course: {pages, modules: [{chapters: [{pages}]}]}}. The first page of a chapter is its front page (is_chapter_front_page: true); the course front page (/) is always first in /course/pages; the default module is always first and has no name.
60patch_course_structure ops: replace fields (module name; chapter name, color, opens_at, deadline; page title, url_path, hidden), remove (field to null, or an entity or page range), add (module, chapter or page; a chapter gets a front page; a page may carry blocks), move, copy (page or chapter; new ids, -copy suffix), reorder (value: exactly the current ids in the new order).
61- Chapter numbers and /chapter-N paths are recomputed after every call. A chapter page's url_path is its last segment, e.g. \"loops\" for /chapter-2/loops; the front page's path is always /chapter-N. A hero section's label shows \"chapter N\" by itself while useDefaultTextForLabel is on and the label is unset or \"Chapter number...\"; leave it so, as a hand-set number goes stale when pages move.

67const PUBLISHING_AND_RISK: &str = "\
68Every write stages into your open changeset for the course; later calls build on it, and reads show it unless state is published. list_changesets shows it, discard_changeset drops it, publish_changeset publishes it.
69A change is risky only in live content (not draft, not test mode, not a hidden page, not a chapter that hasn't opened):
70- removing an exercise block whose exercise has submissions, or a page or chapter containing one
71- removing a visible page or an open chapter
72- moving a deadline earlier or adding one to an open chapter; moving an open chapter's opening time later
73- changing an exercise's own deadline so that the deadline that applies to it moves earlier, or it gets one, while its chapter is open
74- changing a completion policy or the module completion requirement after completions exist; turning chapter locking on or off
75publish_changeset refuses changesets with risky changes; the teacher publishes those on the review page. Size alone is never risky; moving exercises is never risky, even when the move changes which chapter deadline applies. Publishing fails if a staged page or entity changed live meanwhile: drop just those with discard_changeset and entities, read their published state again and redo your edits to them.
76A write fails with staged_state_changed when a parallel call changed what it read; read again and repeat it.
77After publishing, get_history lists changes and revert_change undoes one write call.";

82const CITATIONS_AND_GLOSSARY: &str = "\
83Citations are written in rich text as \\cite{key}, \\cite[postnote]{key} or \\cite[prenote][postnote]{key}, where key is a reference's citation_key. References hold one BibTeX entry each (fields citation_key, bibtex); the entry's key must equal citation_key and be unique in the course. The server checks only an entry's structure; pages render citations with a stricter parser, so keep to standard BibTeX and preview a page that cites a new entry.

87const RICH_TEXT: &str = "\
88Rich-text attributes hold the HTML the editor stores, with inline formats only, in exactly the shapes the editor produces (see rich_text_formats). No block-level tags, scripts, event attributes, style attributes or inline images. Inline math is [latex]x^2[/latex], rendered with KaTeX like moocfi/latex blocks; inside it only &amp; is decoded. 90const EXERCISES: &str = "\
91An exercise block on a page holds only the exercise id (exercise_id in reads). get_exercise reads the exercise: name, tasks, review settings and its instructions; patch_exercise edits the name, the own deadline, each task's instructions (/tasks/<task id>) and the review instructions (/review_instructions) with page-content ops. 100/// The `guide` tool's result: the guide of each block type and topic asked for, or with neither
101/// asked for, the index of both. `schemas` may be `None` only when only topics are asked for.
102pub fn answer(
103    schemas: Option<&BlockSchemas>,
104    block_types: &[String],
105    topics: &[GuideTopic],
106) -> Result<Value, EditError> {
107    let mut answer = Map::new();
108    if let Some(schemas) = schemas {
109        if block_types.is_empty() && topics.is_empty() {
110            return Ok(index(schemas));
111        }
112        if !block_types.is_empty() {
113            answer = blocks_guide(schemas, block_types)?;
114        }
115    }
116    if !topics.is_empty() {
117        answer.insert("topics".into(), topics_guide(topics));
118    }
119    Ok(Value::Object(answer))
120}

122/// What the guide covers: its topics and the block types each page type allows.
123fn index(schemas: &BlockSchemas) -> Value {
124    json!({
125        "topics": GuideTopic::ALL,
126        "block_types_by_page_type": schemas.page_types,
127        "schema_version": schemas.version,
128        "usage": "Call guide with block_types and/or topics for details.",
129    })
130}

132/// The hand-written guide of each topic.
133fn topics_guide(topics: &[GuideTopic]) -> Value {
134    json!(
135        topics
136            .iter()
137            .map(|topic| json!({"topic": topic, "text": topic.text()}))
138            .collect::<Vec<_>>()
139    )
140}

142/// Each block type's schema, nesting rules and an example add op, with the rich-text formats.
143/// Errors on an unknown block type, listing similar ones.
144fn blocks_guide(
145    schemas: &BlockSchemas,
146    block_types: &[String],
147) -> Result<Map<String, Value>, EditError> {
148    let blocks = block_types
149        .iter()
150        .map(|name| block_guide(schemas, name))
151        .collect::<Result<Vec<_>, _>>()?;
152    Ok(Map::from_iter([
153        ("blocks".to_string(), Value::Array(blocks)),
154        (
155            "rich_text_formats".to_string(),
156            json!(schemas.rich_text_formats),
157        ),
158        ("schema_version".to_string(), json!(schemas.version)),
159    ]))
160}

162fn block_guide(schemas: &BlockSchemas, name: &str) -> Result<Value, EditError> {
163    let Some(schema) = schemas.blocks.get(name) else {
164        let suffix = name.rsplit('/').next().unwrap_or(name);
165        let similar: Vec<&String> = schemas
166            .blocks
167            .keys()
168            .filter(|k| k.contains(suffix))
169            .collect();
170        return Err(
171            EditError::new(EditErrorCode::NotFound, format!("no block type \"{name}\""))
172                .with_details(
173                    json!({"similar": similar, "all": schemas.blocks.keys().collect::<Vec<_>>()}),
174                ),
175        );
176    };
177    let page_types: Vec<&PageType> = schemas
178        .page_types
179        .iter()
180        .filter(|(_, names)| names.iter().any(|n| n == name))
181        .map(|(t, _)| t)
182        .collect();
183    let mut example_op =
184        json!({"op": "add", "path": "", "position": "end", "value": schema.example});
185    if schema
186        .allowed_parents
187        .as_ref()
188        .is_some_and(|p| !p.iter().any(|p| p == "root"))
189    {
190        example_op["path"] = json!("/<parent id>/innerBlocks");
191    }
192    Ok(json!({
193        "name": name,
194        "title": schema.title,
195        "description": schema.description,
196        "attributes": schema.attributes,
197        "allowed_parents": schema.allowed_parents,
198        "allowed_children": schema.allowed_children,
199        "template": schema.template,
200        "template_lock": schema.template_lock,
201        "page_types": page_types,
202        "enabled_by_course_setting": schemas.course_feature_gated_blocks.get(name),
203        "example_op": example_op,
204    }))
205}

262    #[test]
263    fn index_blocks_and_topics() {
264        let index = index(&schemas());
265        assert_eq!(index["topics"].as_array().unwrap().len(), 7);
266        assert_eq!(index["topics"][1], json!("course-structure"));
267        let guide = blocks_guide(
268            &schemas(),
269            &["core/paragraph".into(), "core/list-item".into()],
270        )
271        .unwrap();
272        assert_eq!(guide["blocks"][0]["example_op"]["path"], json!(""));
273        assert_eq!(
274            guide["blocks"][1]["example_op"]["path"],
275            json!("/<parent id>/innerBlocks")
276        );
277        assert_eq!(guide["blocks"][0]["page_types"], json!(["course-page"]));
278        let topics = topics_guide(&[GuideTopic::RichText]);
279        assert_eq!(topics[0]["topic"], json!("rich-text"));
280        assert!(topics[0]["text"].as_str().unwrap().contains("[latex]"));
281    }
